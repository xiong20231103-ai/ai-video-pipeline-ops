# Repository workflow

- After every completed update to this project, run the relevant checks, commit the intended project changes, and push them to `origin/main`.
- Do not include runtime databases, logs, cache files, simulation state, API keys, credentials, tokens, or other secrets.
- If validation fails, fix it before pushing. If pushing is blocked by authentication or network access, report the blocker clearly instead of claiming the repository is synchronized.
- Keep deployment documentation and `config.json` path examples updated when configuration or directory conventions change.
