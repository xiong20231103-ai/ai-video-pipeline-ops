# 补链排队提示

旧页面及 V2 使用同一快照内 receiverQueue 的 pending_confirmation 补链记录关联父 taskId、canonicalTaskId、日期、项目和材料，显示已收到链接数、排队中或等待确认启动；仍保留真实素材缺口。重复子任务编号只计一次，已撤回/已合并/已导入历史不作为排队证据。读取队列失败时不推测收到状态。

有补链排队时，旧页弹出说明，V2 禁用快速补链并隐藏项目再次补交按钮。部分补链保留未补交数量，提示等待已有任务处理后再补，避免旧接收端不具备并行去重时重复创建。

验证：234 项前端测试含13项新增旧页/V2状态对照，typecheck、lint、功能清单检查和静态构建。只读展示，不修改接口、任务状态、队列调度或生产目录。未部署。真实生产回执不能由隔离测试替代。
