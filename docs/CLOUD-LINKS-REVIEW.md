## 本次实现

1. 独立links.db与shots目录；来源实例/平台/视频ID/判图轮次幂等，旧事件不能回退决定。
2. 两个状态独立；confirmed+waiting表示已收录待递交。未进入审核的候选review为空，保留rawReviewState，
   不伪装成pending或expired；raw pending计数与可展示计数分开。
3. 公司展示图在原展示入口生成后保存压缩副本，JPEG80、长边1600以内、600KiB以内；不传多帧或exemplars。
   发件箱事件与图片同事务保存，2GiB逻辑图片上限，淘汰最旧图片但保留事件并报警。
4. 独立上传进程只操作outbox，通过本机鉴权服务导出material.db候选与正式链接。
   每天北京时间18:00增量导出，错过后开机登录补传，失败指数退避；状态指纹去重。
   单轮最多25请求、30秒轮询，配合云端60次/分钟限速。导出时新入队的数据当轮可上传。
5. 截图SHA256去重；pending不清理，处理后15天按决定时间，历史未知按首次上传时间。
   上限5GiB，优先清理已处理截图，容量拒收后状态与链接仍入库且页面报警。
6. 查看页只读，日期/平台/审核/投递筛选，历史分页加载，截图缺失时链接保留。
   独立03:30清理/在线备份timer文件，保留7份DB，不备份图片；未安装timer。
7. 家里cloud_home复用现有mf-review-media插件结构化附件协议；保存冻结快照，重发不重新选素材。
   丢图或哈希不匹配时整批返回明确失败，不把只有链接的结果当成功。当前可只读查看尚未通过配额核验的图片。
8. 每日任务箱复用原submitter.formal_payload/denor_payload，可固定batch ID；正常4条/DENOR21条样例
   已通过真实接收端_prepare_batch_payload校验。保持正式合同和DENOR输出计划，不改判图。
9. 递交复用原串行CommandQueue：先冻结链接集合和请求编号，再明确confirm；只核验完整接收回执后标sent。
   命令发送许可显示awaiting_receipt，超时unknown不能自动换ID重发。补链仍继承原父任务。
10. 云端动作流到公司只通过本机受保护API回写，调用原Pipeline方法；指纹变化返回冲突。
    本机确认动作和回执账本同事务，重复动作不重复收录；仅本机确认成功才推进游标。
    所有含凭据的请求拒绝重定向；日志不写令牌、HTTP响应正文或配置内容。

## 必须解决的阻断项（请优先审查）

1. **云端可展示配额与稳定批次**：当前来源事件displayable=false，conditions.quota=not_evaluated。
   不能打开远程收录开关。需要复用reviewflow的字幕/分类目标/补链需求/借用规则，
   固定批次和限额，在云端事务内约束多人/两地的合计收录数，避免单条决定越过类别或项目配额。
2. **两地操作归属**：指纹冲突只能发现本地已变化，不能阻止公司和家里同时确认/递交。
   需设计并测试每批次的交接/预留，以及公司收录、放弃、撤回、移动、原递交器等全部入口的冲突行为。
   同时核对现有sites.py整库主备同步，防止它覆盖新增账本或把旧数据推回。
3. **日期语义**：导出的候选date目前来自创建时间；源reviewflow普通批次依赖当天目标，
   Pipeline接受历史候选时按当前日期入库。需区分采集日期、生产批次日期、决定时间，
   验证跨午夜及10.15等历史补链，不得把updated_at当决定时间，也不能擅自回填日期。
4. **现有递交窗口**：正常接收端任务箱落盘与回执落盘之间有窗口，未发现直接查询原回执的GET接口。
   当前unknown保留原命令、不自动重试；还需给用户可操作的接收端对账/恢复入口。
5. **历史截图**：历史链接可独立只读限速补传，但最近15天展示图的发现与补传未闭环。
   不能用exemplars、多帧原图或WSL review目录代替已限定的数据源。
6. **部署验收**：尚未测试真实Tailscale、Gateway原生附件、WebChat刷新、开机任务、故障恢复和云上实际备份占用。
   23/10项测试不能替代最初要求的全部场景和10轮连续验收。

请审查后给出阻断问题、建议补丁与可批准的范围。当前最多评估“云端副本/只读查看”是否可进入部署准备，
不能把完整远程确认递交标成完成。
