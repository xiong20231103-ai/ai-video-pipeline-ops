# 内容判定、窗口耗时与重复禁用预检

本变更仅供审查：不更新正在运行的 Dashboard，不启用 observe，不恢复生产，不发业务请求。旧版三轮预检及汇总保留原位置；私有基线清单另记其路径/大小/哈希，不复制到仓库。

## 判定口径

- 目录只比较观测到的子项名称集合和类型。新增、删除、改名或类型变化使窗口失败。目录的 inode、mtime、ctime 变化本身不使窗口失败；最终时间戳保留在 filesystem 证据中，同时记 stat-only。
- 明确 files 状态输入：元数据变化时重新读取并比较 SHA256。同内容替换记 rewrittenSameContent；真实内容变化报 state_changed_in_window，不发布该窗口。读取过程中遇到替换最多补读一次，不能无限重试。
- trees 小文件：仅非私密文件名的 .json/.txt/.log，单文件不超过 1 MiB。窗口开始留内容摘要，结束仅对元数据变化项重读；相同摘要记 rewrittenSameContent，不同或读中变化标 hashPending/writing_or_changed，不使整个目录窗口失败。已知私密类型不读取。小文件所有实际读取（含一次替换补读）共用每轮 32 MiB 上限；耗尽后摘要待补，不伪造一致。
- 媒体和大文件在正式窗口/预检中只记录元数据，摘要为 pending，不读取内容。旧版独立 DigestCache 工具的可选分块能力保留，但本路径不调用它读取媒体。
- .lock 只记 kind/exists/existence-only，不读内容、不比较大小、inode 或时间戳。锁文件真的新增/消失仍属目录成员变化，不能凭空忽略。
- shallow 只记录一层名称与元数据，不读该层文件内容，不递归未授权子目录，未捕获目录依然不可比。

Windows 文件句柄 fstat 与路径 stat 的 ctime 语义可能不同，DirEntry.stat 也可能不给 inode/device。因此句柄身份核对用 kind/size/mtime/inode/device；证据中的 ctime 取路径 stat。枚举使用一次不跟随链接的子项 stat，目录进入时仍检查所有祖先，拒绝链接、重解析点和特殊文件。读取内容时另检查完整路径；没有取消这些边界。

## 诊断和计时

`stabilityChanges.changes` 只列前 50 个不同的“逻辑路径、变化类型”组合；超过明确 changesTruncated。类型为 stat-only、content-change、added、removed、type-change，未取得可比内容时为 stat-unverified。计数保留全部事件，不写文件正文、绝对路径或异常原文。

报告提供 rewrittenSameContentCount、statOnlyChangeCount、smallFileReadBytes、摘要待补数。状态窗口失败时，series 的失败行仍带固定代码、逻辑路径和已测阶段时间，增量为空，不算零。继续遵守失败不自动重试。

每轮 phaseTimings 分列：进程探测、状态读取/去重、SQLite 在线备份、DB 块摘要、状态复核、三个目录窗口总计、小文件摘要、目录枚举/比较。directoryStability.windows 列每个窗口秒数、枚举/比较、小文件摘要、夹具间隔、条目数及 within20Seconds。原先 measuredSingleRoundReadBytes 是输入逻辑字节，并非所有物理 I/O；树中小文件读取单独计数，不混作 DB 输入或实际落盘容量。

## 20 秒与拆分门禁

正式 aligned_capture 上限只能为 20 秒或更短，不能配置 21～60 秒。状态/数据库预检输入窗口也是 20 秒；SQLite 取得剩余时间，目录枚举、每块读取及核对均检查截止。预检的三个目录探测各自上限 20 秒，不能把三者总耗时误称同一个窗口。超时记不可测，不发布合格证据；阻塞的操作系统 I/O 或 SQLite 调用可能晚于截止才返回，返回后仍拒绝该窗口，不能声称已硬实时中断。

修改前实际三轮总耗时分别为 80.579、71.438、72.625 秒；SQLite 为 1.704、1.110、2.047 秒。旧版未给枚举/摘要分段计时，剩余时间不能准确归因。代码可确认旧版每个目录窗口做两遍全枚举，且每个子项重复检查祖先；本次将重复祖先检查压到目录边界，并报告上述阶段，宿主重测才能定量核实。

隔离夹具：40 个日期、882 个节点、连续同内容原子替换，三个目录窗口约 0.06～0.09 秒，均低于 20 秒。它验证算法与退化门禁，不证明真实宿主一定达标。

**真实宿主暂待重新预检。** 若任一窗口仍超过 20 秒，不能加长上限或称验收通过；拆分方案如下，须先交 Claude 核对新的白名单/计划：

1. 按明确的状态/命令、当前日期输出、下载、音频、草稿子树分片；历史交接按固定日期范围分片，E 根仍只浅采集。每片给独立 source/window 身份及起止时点。
2. 原状态/DB 输入独立取得一致快照；不同片的时点不冒充同一时点。跨片需要的事实在未取到匹配窗口前标不可比，不能把各片相加当作完整零差异。
3. 每片保持 20 秒、32 MiB 小文件额度及原总存储额度；先多轮预检，再核对实际宿主耗时。不能为降耗自动缩小或忽略旧代码实际会读的范围。
