# 影子采集和隔离回放串接（#55 后续）

## 交付边界

新增 CapturePublisher，将已经旁听到的响应与显式文件/元数据计划做稳定窗口采集，存入受配额限制的块存储，原子发布 ready 清单。无网络、无业务 POST、不启用引擎；异常只返回固定码，不记录路径或异常正文。HTTP 观察超过90秒、输入变化、进程身份变化、容量不足均拒绝，不删除旧证据，不自动扩容。默认总批准容量不能超过现有2GiB上限；原记录器保留目录必须显式计入 retained_roots。

shadow_replay_worker 只作为独立进程命令运行：消费已保留快照、严格回放 R1/R5只读接口或R2无损导入比较，产出差异/不完整报告。禁止在采集宿主线程执行 Oracle：其冻结I/O需要局部替换Python全局模块，必须由进程隔离保护真实读写。采集标记 emitterPid 与回放PID一致时拒绝。报告永远不自动宣称真实影子通过，R5只读不等于实际清理验收。

## 精确包准备（仅暂存，不安装）

审查通过后，将占位提交号替换为最终40位提交：

```
python -B -m tools.shadow_stage_package --repository <隔离仓库> --commit <已审查40位提交> --out <全新独立暂存目录>
```

包仅从 git 对象生成，逐文件 SHA256，不从工作目录复制。它不包含生产配置、数据库、日志、密钥、素材或旧旁听证据，不注册计划任务、不启动/结束进程、不写 engine-settings.json/migration-settings.json。已存在目录、符号链接及源码依赖缺失均拒绝。

## 主机安装仍须过的门禁

1. #52/#53/#55与本PR经Claude审查，当前真实生产批次完成后才安装。
2. 以只读盘点得到的根目录、明确状态文件、目录元数据树、进程身份与现有HTTP端口形成 reviewed capture plan；每一项都验证闭合。不得用任意递归复制或不完整目录缺省为空替代。
3. 确认现有GET宿主：代理只读取部分外部数据，R1/R5回放还需要Dashboard原有接收器及控制面GET事实。#55的代理观察入口本身不能代替Dashboard外部事实。不能为补事实额外轮询、改变ETag策略，或把过期响应伪装成当前窗口。
4. 在隔离宿主中验证观察绑定、采集线程退出、维护标记、看门狗、隐藏启动及回滚；生产启动器参数尚未改变。本PR不提供假装可用的安装命令。
5. 最终安装前备份原包及启动入口、写一条精确回滚命令；安装后确认旧系统行为不变、心跳和队列正常、cleanup及autoRecovery仍关闭。任何验证失败立即恢复该次备份。

尚缺Dashboard GET宿主绑定和实际根目录闭合计划；没有这些，不能标记可安装完成。R3完整运行端口记录、R5真实保护/执行记录、R2时间线口径及两批完整真实证据仍待验收。

## 验证

97项影子相关隔离测试通过，含新增16项采集/队列/离线消费者测试。测试拦截真实HTTP、进程启动和生产写入；Windows asyncio内部socketpair需宿主权限，所以使用同一隔离runner在宿主执行。无真实批次样本被计为通过。
