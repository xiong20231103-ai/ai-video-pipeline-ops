## 已实现边界

- compatibility_logic.py 补齐其他模块未提供的历史回执及 HTTP handler，逐函数来源行号在 r6-provenance.json。固定旧源 f78db5a，不 import app 或执行旧启动逻辑。
- runtime_ports.py 只接受显式 base_dir/state_dir/config，分配常量、锁和票据；不发现或读取已安装生产配置。尚未作为生产工厂启用。
- composed.ComposedSession 将 R1 投影、R3 普通命令、R4 恢复、R5 清理和剩余 handler 绑定在同一个 namespace。严格清理装饰器内部闭包也重绑定；共用 STORE/COLLECTOR、控制命令锁、清理锁、ContextVar 和票据。
- replay_composed 显式替换路由对象，使请求调用候选 handler；比较响应、DB/文件副作用及 GET 请求序列。隔离 HTTP 端口仍由 R0 提供，不会连接生产。

1. 持久投影、原 ExecutionWorker 台账接点、原生 FastAPI 参数验证和本机只读兼容服务已实现候选代码；实际启动/生产接线尚未验收。不能新起第二执行者，也不能把每次重启的空内存投影当持久权威。
2. R4 协议 2 工作台适配及旧版回退包装已实现候选代码，要求审查过的源码哈希和原工作台权威路径；实际部署必须与工作台协议修复配对，不能单独上线。
3. 旧 GET 对账写入和所有旧写入口必须归属同一门禁；保留旧 Dashboard 的 HTTP 写入口会形成双权威，不能只切云端地址。
4. 8765 与 18790 的反向依赖、watchdog/登录自启/接收器依赖必须逐个盘点并消除同步循环等待，再确定兼容读入口。不能仅改名 app.py 后启动同一代码。
5. 同步 main 的 R0/R2 后续审查修复；全部 R4/RC/R5 条件正反边界、完整批次真实影子零差异、用户/Claude 切换验收均不能用本轮合成回放代替。

## 计划切换与回退约束

- 切换只能由 Claude 在用户同意且生产空闲时执行；队列 leased/sent/unknown 清零、双方回执和恢复请求对账后才可切。
- 切换前一致性备份台账/配置/启动项，所有本地与云端写入口先关闭，验证旧执行者退出后才授予新执行者唯一权威。失败保持关闭，不自动回落到旧 POST。
- 回退同样先排空并收回新权威；对账切换后新增命令与回执，不能把旧 DB 备份覆盖到新命令记录上。
- 旧 Dashboard 源码、环境、配置和原启动方式至少保留两周；明确可切回才允许最终退休。此次不运行任何上述操作。

所有 capability 仍为 enabled=false / realShadowPassed=false / switchAccepted=false / legacyRetired=false。
