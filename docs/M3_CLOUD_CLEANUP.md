# M3 云端清理桥接（待 Claude 审查；未部署）

本 PR 基于 M2b，依赖单独的家里 Dashboard 清理契约 PR。只连接既有管理弹窗、云端串行队列和家里已部署的 H2 待删区，不实现第二套文件删除。不合并、不部署、不操作生产。H2 其余清理类别的权威映射缺口仍单独等待设计确认，本 PR 不声称完成该扩展。

## 合同和保护

唯一新增执行白名单：`POST /api/controls/cloud-cleanup/preview`、`POST /api/controls/cloud-cleanup/execute`。三类 ID 数量/长度为草稿 500/160、音频 2000/80、生产文件 5000/80；pending 必须空列表。先验证字符串、去空去重，再限数量。拒绝路径、盘符、分隔符和未知字段；保留 `unidentified:hash` 类不透明 ID，让家里返回保护原因。执行始终传原全部选择，不能剔除 blocked 条目改变音频整体拒绝语义。

家里签发不超过 120 秒、进程重启失效、一次性消费的票据；绑定原对象、snapshotToken、种类、includeUnknown、确认串。云端再绑定同一登录账号的已完成预览回执及原选择。预览回执到达云端后独立最多 120 秒可发起；排队有效期不超过 120 秒和票据 expiresAt。云端收件、发送许可、代理发送前分别检查，家里最后重新盘点并判断票据，不信任客户端时间。浏览器用 performance.now 测量预览接收后时间；票据只在页面内存，localStorage 仅存命令编号和指纹。重载后只按原编号查回执，不重新 POST。

开关 `cleanup_enabled` 默认 false。必须同时满足：新代理能力、Dashboard 新能力 GET 的成功缓存不超过 60 秒且 retentionDays 精确整数 3 / protocol 精确整数 1 / forbiddenDraftRootProtected=true、summary 源扫描及缓存合计不超过 60 秒、家里健康在线、没有 unknown 命令。能力 GET 仅用户打开管理窗口、点击“检查清理通道”，或窗口打开期间每 30 秒按需请求；无人使用不主动轮询。

代理能力放在 heartbeat 顶层 cleanupProtocol，execution 字段保持旧格式。旧云端忽略额外顶层字段，因此云端回滚不使新代理心跳因严格 execution 字段校验而失败。旧代理不带能力时新云端关闭清理。

预览超时 90 秒；执行 HTTP 最长 900 秒，云端发送后 960 秒转结果不明。此时整个串行写通道仍阻塞，绝不自动重发。首次发送窗口与执行完成等待分开。优雅停止会等待当前写通道完成，更新必须先暂停云端并等待清理结束，不能强杀。不能将 HTTP 回执等同全部对象清理成功，页面保留家里部分失败、逐项 blocked 等原始结果。

复用原管理弹窗和勾选列表，增加清理前手输原确认串；人工/未知草稿、生产测试文件保留额外确认。立即清空待删区先预览，再明确说明永久删除，并两次手输 EMPTY_PENDING_DELETE_NOW。只调用家里现有 H2 purge，不写永久删除逻辑。生产数据从不由本 PR 实测。

## 验证

- 完整隔离套件：310 项通过，1 项本机权限跳过；网络/进程及生产写入阻断。
- 九项 M3 新测试：closed contract、权限/CSRF、开关/新旧代理、Dashboard 能力和新鲜度、账号/原选择/票据、排队/许可/发送前过期、长清理未知不重试、ASGI 部分失败保真、heartbeat 兼容。
- 六个真实无头浏览器场景（所有网络拦截）：勾选→预览排队→GET→手输→执行→部分结果；过期不发送；重载只查原 ID；待删区双手输；测试文件额外确认；人工未知额外确认。无真实家里/云端请求、无桌面窗口。
- 旧日期按需读取沿用现有 cache_key 和 202 取数流程，未另加家里定时扫描。

## Claude 部署顺序（用户未授权本轮部署）

1. 先审查家里和云端两个 PR；清理扩展缺口另按确认处理。流水线空闲时由 Claude 部署家里新契约和独立代理，保留生产目录/代理源码各自现有备份和回滚入口。不得把未审查的清理类别加入白名单。
2. 云端先执行既有 command_admin pause --wait 以排空；若有 sent/unknown，必须等实际请求结束并人工对账，不得强行重置。使用现有备份部署流程保存原 release、只读 SQLite backup、权限受保护的配置及防火墙/Serve 状态，生成 `sudo /root/<本次备份>/rollback.sh` 一条回滚命令后再切换新 release。新增表为 additive，回滚不回放旧数据库或命令。
3. 新 release 先保持 cleanup_enabled=false；不新增公网端口、不启用 Funnel、不修改 Serve/防火墙。验证旧命令、登录、飞书通知和备份均正常；再只读确认新代理能力、home capabilities、H2 三天待删区及禁止 JianyingPro Drafts 保护。
4. 按已授权独立测试样本验证后，由 Claude 审查决定启用开关；先备份配置、生成对应还原命令。SPC 德语仍暂停；不以安全继续验证清理。
5. 回滚先将清理开关关掉，暂停并排空队列/人工核实 unknown，再执行部署前打印的唯一 rollback.sh。先回滚云端或代理均保持旧格式 heartbeat 兼容；Dashboard 能力消失或缓存过期后 canCleanup=false，不能绕过。
